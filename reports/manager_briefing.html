The concrete operation lever · NEW

It’s the machine — and we can prove it now

With real machine IDs added, the machine a bladder runs on significantly affects its life even for the same part (η² = 0.078, p = 0.0004). This is the “operation” share made concrete — and it’s ours.

Lift PAP12 to PAP11’s proven ceiling and every one of those 17 units gains. Next worst is PAP18 (37%). Worst presses fleet-wide by premature rate (n ≥ 12): PAP13 33%, PAP21B 29%, BNS20 28%.   • PLC air-purge interlock + handling SOP — kills the deform failures (80% ours).
  • Trace the 2024 Q3 spike on the PAP21B & BNS line — process change or consumable batch?

Method

Life is right-skewed (Weibull β ≈ 1), so all tests run on log-life or use the non-parametric Kruskal–Wallis, reporting effect size (ε² / η²), not just p. Blame is separated by a nested variance decomposition: part (design) → lot within part (batch) → within-lot residual (operation) — the standard batch-vs-within-batch split used for supplier-vs-process diagnosis in manufacturing. Machine and position (C / AR / R) tested within-part via Type-II ANOVA (N = 417, machine IDs joined from the event log).

Read the fine print in the meeting. “Us” is the residual after design + batch, so it also absorbs random noise — treat 54% as an upper bound. Lot is still proxied by install date (no true lot number yet), and the 2024 Q3 removal spike needs a maturation-bias check — recently-installed units still running aren’t in the data — before it’s claimed as a hard event. The direction of every finding is solid; the exact percentages are soft.
